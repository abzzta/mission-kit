### 1.1 Corrected - homes promised and never named

| | |
|---|---|
| **Old** | *that entry has been dissolved and its load-bearing content distributed to the homes named below.* |

The commit that dissolved the umbrella axiom named all three; the charter never did.\

### 1.2 Corrected - situated moves called declinable

| | |
|---|---|
| **Old** | *you reach for it when a specific task touches its domain, and you can reasonably decline it.* |
| **New** | *you reach for it when a specific task touches its domain, and it does not apply when no task does.* |
| **Kind** | correct |

The old wording contradicts `M0` as ratified, which says a procedure is declined only by not being in its situation.
**The evaluation confirmed this was live, not theoretical:** all three original-version evaluators quoted the old phrase as the defining mark of a situated move, and one wrote *"Declining is allowed only for situated moves."*\
No evaluator noticed the conflict with `M0`, because none held `M0` - which is why a correction of this kind has to be applied to both charters together.

### 1.3 Corrected - multi-tag binding, by director ruling

| | |
|---|---|
| **Old** | *An axiom is in force for a system if, and only if, that system's architecture satisfies the axiom's `applies-to` tags.* |
| **New** | *...satisfies **at least one** of the axiom's `applies-to` tags. Tags are alternatives, not a conjunction.* |
| **Kind** | correct |

**All six evaluators raised this independently, in both versions.**\
"Satisfies the tags" could mean every tag or any one, and the matrix - listing each axiom under every tag it carries - leaned toward any.\
The ambiguity has been present in every revision of this charter.\
A downstream audit once cited the charter's "multi-tag semantics" as if settled; the only text was *"An axiom with multiple tags appears under each tag it carries"*, which describes how the matrix is drawn and not how an axiom binds.\
**Ruled by the director: any tag suffices.**
